# 赛道二：白鹭湾新经济总部功能区巡检孪生

日期：2026-11-01

在锦江区三维城市上，把白鹭湾新经济总部功能区做成一个园区巡检孪生台：机器狗、无人机和安保员沿真实道路巡逻；发现异常后，系统按事件类型自动派单，处置完成后智能体回到岗位。对应赛道二列出的切入点"天地人一体化园区智慧巡检平台"和"AI 机器狗园区安全巡检"。

**设备、事件和异常检测全部是模拟的，没有接入任何真实设备或数据流。**

## 场景范围

功能区按白鹭湾科技生态园 A–E 区处理。OSM 里没有"新经济总部功能区"这个对象，这个对应关系由项目方确认。

| 分区 | OSM way |
| --- | --- |
| A 区 | 1568670319 |
| B 区 | 1191850931 |
| C 区 | 1568670316 |
| D 区 | 1568670317 |
| E 区 | 1568670318 |

五个分区合计约 450 m × 640 m，中心约在 30.586°N、104.111°E。巡检点位取各分区临街的路口，没有用地块中心，因为地块中心离路网 100 m 以上，智能体沿路走不到。

## 能做什么

- **自动巡逻**：机器狗沿道路环线巡逻，无人机沿各分区点位连成的直线航线巡航，安保员在驻点待命。
- **发现异常**：事件发生时先处于"未发现"状态。智能体巡到检测半径内才会发现它；60 秒内没有人巡到的，由视频监控兜底发现。
- **按类型派单**：每类事件对应一组处置步骤。高风险事件同时派出多类智能体，其余的先空中复核，再派人到场，减少人力占用。
- **事件落在设施旁**：烟雾落在垃圾收集站、电动车充电棚或配电房，积水落在路口排水口，闯入落在围界，占道落在大门或装卸区，路灯故障落在园区周边的路灯。
- **文字指令**：用本地规则解析，离线可用。例如"让机器狗去 C 区巡查""无人机去 D 区看看""E 区出现积水""召回所有智能体""全部巡查一遍"。
- **一键演示**：按固定剧情走一遍，用时约 2 分钟（1 倍速下的模拟时间），画面上方配字幕。字幕里的地点和发现者取自实际发生的事件，不是写死的文字。
- **统计**：待处理、已处置、平均响应、平均闭环、累计里程。另有 1×、2×、4× 倍速和暂停。

## 智能体

| 名称 | 类型 | 速度 | 检测半径 | 职责 |
| --- | --- | --- | --- | --- |
| 巡检犬 01 | 四足巡检机器人 | 3.5 m/s | 55 m | 沿道路巡逻、靠近取证 |
| 无人机 01 | 多旋翼巡检无人机 | 9 m/s | 100 m | 沿航线巡航、空中复核与跟踪 |
| 安保员 01、02 | 电动巡逻车 | 8 m/s | — | 驻点待命，到场处置 |

道路环线长约 1.4 km（1435 m）。机器狗绕一圈约 410 秒，无人机约 137 秒。

## 事件类型

| 事件 | 等级 | 处置步骤 | 派单方式 | 出现条件 |
| --- | --- | --- | --- | --- |
| 占道障碍 | 一般 | 空中复核 → 现场清理 | 先后 | 任何时候 |
| 路面积水 | 一般 | 空中复核 → 设置警示 | 先后 | 仅雨天自动出现 |
| 异常闯入 | 较急 | 空中跟踪、靠近取证、现场劝离 | 同时 | 任何时候 |
| 烟雾告警 | 紧急 | 确认火情、现场处置 | 同时 | 任何时候 |
| 路灯故障 | 提示 | 报修检查 | — | 仅夜间自动出现 |

异常闯入的"靠近取证"只在机器狗离事件 260 m 以内时才派。机器狗太慢，离得远就跳过这一步，不苦等。

自动出事件的间隔是 28–50 秒（模拟时间），同时未结的事件最多 3 起。任何事件都可以用面板按钮或指令手动触发，不受昼夜和天气限制。

## 模拟结果

用真实路网和随机种子 11，开启自动出事件，模拟 20 分钟：

| 指标 | 结果 |
| --- | --- |
| 已处置 | 22 起 |
| 结束时未结 | 3 起 |
| 平均响应 | 22 秒 |
| 平均闭环 | 79 秒 |
| 累计里程 | 29.0 km |

统计口径：

- **平均响应**：从事件被发现，到第一个智能体到场。
- **平均闭环**：从事件被发现，到全部处置步骤完成。

两项都从"被发现"开始算，不含事件发生到被发现的那段时间。这些数字只说明模拟参数下的节奏，不代表真实设备的性能。

## 技术路线

- **三维城市**：OpenStreetMap 数据经 `tools/build-city.mjs` 构建成二进制城市数据，浏览器用 three.js 渲染。白鹭湾湖面原先缺失，原因是裁剪脚本丢掉了 OSM 多边形关系。现在 `tools/clip-sichuan-pbf.py` 会读取湖泊类关系（不收河流关系，避免桥梁识别多出假桥）。
- **寻路**：智能体沿已有路网走，复用 `src/tour/planner.js` 的 `planPath`。
- **巡检模拟**（`src/patrol/`）：`sim.js` 是不依赖渲染的纯逻辑，负责巡逻、发现、派单、处置和统计，同一个种子每次走出的过程一样。`zone.js` 定义分区、智能体和事件类型，`command.js` 解析指令，`demo.js` 编排演示，`view.js` 和 `ui.js` 负责三维表现与面板。
- **园区布置**（`src/ecopark/`）：依据真实的分区轮廓、建筑占地和道路，排出围界、大门、配套设施、停车区和事件落点，再写进现有的构件渲染管线。和这些布置重叠的行道树与路灯会被移除。

## 真实与模拟的边界

| 来自真实数据 | 示意或模拟 |
| --- | --- |
| 分区轮廓、道路、建筑占地（OSM） | 所有智能体、事件和检测结果 |
| 白鹭湾湖面等水体（OSM） | 建筑高度（OSM 无数据，用估计值） |
| 巡逻环线走在真实道路上 | 建筑外观（铝板加窗洞的办公楼样式） |
| | 围界、大门、设施、停车区的种类与位置 |
| | 排水口（取自路口节点，不是实测的排水设施） |

## 已知限制

- **雨天没有接进模拟**：场景切成雨天时，模拟并不知道在下雨，所以路面积水不会自动出现，只能手动触发。
- **夜间只在演示里联动**：一键演示切到夜景时会通知模拟，手动切换夜景则不会，所以平时路灯故障不会自动出现。
- **画面没有人工验收**：截图工具一直返回空图，大门、设施、停车区、夜景和演示字幕的视觉效果都没有亲眼确认过，需要在浏览器里看一遍。
- **数据时间戳**：城市数据头里的 `osmTimestamp` 保留了 2026-10-30，因为精细建筑清单按这个时间校验。实际内容来自 2026-10-29 的 PBF 加上湖面修复。
- **测试**：全量 122 项，118 通过，2 失败，2 跳过。失败的 2 项（旧版城市数据加载、精细片区清单缺失）在巡检功能开发之前就存在。跳过的 2 项是数据构建快照检查，本地缺 `data/raw/` 时会跳过。

## 运行与演示

```bash
npm start      # 访问 http://localhost:5173，也可以用 node serve.mjs 8080 指定端口
npm test
```

打开页面后，在右侧面板切到「巡检」，点「一键演示」即可。也可以打开「自动出事件」，或者直接在指令框里输入。
